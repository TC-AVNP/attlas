## Project summaries

### petboard

Fixed the blank page when accessing petboard via its subdomain (petboard.attlas.uk). The Go server already handled dual routing (path-based and subdomain) since commit 0c796bc, but the React frontend had hardcoded `/petboard` in three places: BrowserRouter basename, API prefix, and SSE events URL. Created a shared prefix.ts module that detects subdomain vs path-based at runtime.
**Lines:** L18–L144

### kubernetes-migration

Fixed 9 blocking issues across the full iapetus K8s platform. Major architectural change: vclusters now contain workloads only (no gateway/certs/DNS inside), all routing stays on the outer cluster. CD pipeline splits manifests for dev/stg: workloads deploy to vclusters via ArgoCD, HTTPRoutes with synced service names deploy to outer cluster. ArgoCD now has 9 ApplicationSets covering all 3 stages. DNS fix in bootstrap unblocks cert-manager and the entire TLS chain.
**Lines:** L145–L403

## Lessons

- When migrating a service to a subdomain, the backend routing is only half the story — the frontend's base URL, API prefix, and any hardcoded path assumptions all need to adapt too
- kustomize `namePrefix` does NOT apply to HTTPRoute backendRef names — you must patch them explicitly
- ArgoCD `{{path[1]}}` is invalid syntax — use `{{path.basename}}` or `{{path.segments[N]}}`
- vcluster syncs services to host with predictable names: `{name}-x-{namespace}-x-{vcluster-name}` — this can be computed by CD pipelines
- GCP VMs use metadata DNS (169.254.169.254) that can't resolve external domains — must add 8.8.8.8 BOTH to host resolv.conf AND to CoreDNS
- Two-tier Gateway API routing (Tier-1 → Tier-2 gateway) doesn't work because there's no forwarding mechanism between gateways — use a single gateway with cross-namespace HTTPRoutes instead
