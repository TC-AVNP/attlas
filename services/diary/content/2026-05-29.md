### Subdomain conversion (~25min, 12:30 – 12:55)

- User wanted watchtower.attlas.uk not path-based. Initially built own OAuth (wrong!)
- User pointed to no-own-oauth KB article. Stripped all OAuth code
- Rebuilt with forward_auth + public matchers for beacon/health endpoints

### Identity resolution struggle (~50min, 12:55 – 13:45)

- Beacon showed "anonymous" — all session cookies are HttpOnly, JS can't read them
- Added attlas_user cookie (non-HttpOnly, email only) to alive-server's OAuth callback
- Caddy forward_auth doesn't pass Set-Cookie to client — cookie never reached browser
- Built /api/me endpoint on alive-server: reads session, sets attlas_user cookie, returns email
- Registered /api/me as public path so CORS preflights pass
- Beacon fetches /api/me with credentials:include when cookie is missing
- Added force-relogin in forward_auth verify: if attlas_session exists but attlas_user missing, deny

### Beacon rollout to all services (~20min, 13:45 – 14:05)

- Added script tag to 22 HTML files across 10 services
- Discovered Go services embed templates at build time — rebuilt all 7 Go services
- Discovered Vite SPAs serve from deployed dist, not repo — copied updated dist files
- Added cache-busting ?v=2 parameter to all script tags

### Dashboard UX redesign (~40min, 14:05 – 14:45)

- Removed Apps and Heatmap tabs (system monitoring, not user-focused)
- Built 3-level user drill-down: Users list → User overview (per-app bars) → App timeline (paginated page visits)
- Added hash-based routing so refresh preserves state
- Added date pickers and prev/next pagination on timeline view
- Live tab pauses polling when browser tab is hidden

### Fixing service 404s (~15min, 14:45 – 14:56)

- terminal, afm, openclaw, planner all returned 404 on subdomain root
- Root cause: services use base-path prefixes (/terminal/, /afm/, etc.) but subdomain sends /
- Fixed with Caddy `redir / /prefix/ 302` (not rewrite, which double-prefixes JS API calls)

## Lessons

- Services must NOT implement their own OAuth — the no-own-oauth KB article exists for a reason, read it before building auth
- Caddy forward_auth only copies listed headers to the upstream request on 2xx, NOT Set-Cookie to the client — can't set cookies through forward_auth
- Go services with go:embed require a full rebuild to pick up template changes — editing the file on disk is not enough
- Vite SPA services deploy dist to /usr/local/share/<service>/dist, not the repo path — updating repo dist doesn't update the live service
- Caddy URI rewrite breaks services whose JS hardcodes path prefixes — use `redir / /prefix/` instead of `rewrite * /prefix{uri}`
- The attlas_user cookie pattern (non-HttpOnly, email-only, set via /api/me public endpoint) is the cleanest way to give JS access to user identity without compromising session security
- The port-registry KB entry can go stale — always verify with `sudo ss -tlnp` before picking a port for a new service
