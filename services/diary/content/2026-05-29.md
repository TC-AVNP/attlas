Two sessions today. First, a quick hello-world service (Neko). Then the main event: building Control, a centralized access management service that replaces the scattered auth model where each service maintained its own allowed-users list. Every attlas service now lives on its own subdomain and uses a single OAuth flow through alive-server, with Control as the source of truth for who can access what.

## Project summaries

New hello-world service created from scratch. Minimal Go server on port 7699 serving a single HTML page with pure CSS cat animations. No auth, no database. Deployed at neko.attlas.uk behind Caddy.

### control

Greenfield build of centralized access management. Go server (port 7701) with SQLite storing users, services, and grants. Admin UI with user cards, service toggle grids, search, and pagination. Localhost API for service-to-service auth checks. Major alive-server refactor: cookie domain, X-Auth-User header, Control integration, subdomain-aware forward_auth. All 15 services migrated to subdomains with unified auth. Knowledge base updated with auth documentation.
**Lines:** 350-end

## Lessons

- Port registry in the KB was stale — always verify with `sudo ss -tlnp` before picking a port
- Caddy's forward_auth URI must match the actual handler path exactly (`/api/auth/verify`, not `/auth/verify`)
- Setting cookie Domain=.attlas.uk means existing cookies (without Domain) stop working — users need to re-login once
- DNS propagation can be faster than expected — Caddy tried to provision TLS certs before ACME could verify, but retried successfully after a reload
- The horizontal table layout for user×service breaks down around 10+ services — card-based layout with toggle grids scales better
